## Step 6：生产数据库跨区域迁移与规范化部署（2026-08-30—2026-08-31）

### 目标

- 在不改变业务语义和 golang-migrate 体系的前提下，为小数据量生产库提供安全、可验证、可回滚的跨区域迁移方案。
- 保留本地 Compose MySQL 开发能力，同时明确生产应用通过受管数据库连接配置运行。

### 实现

- 数据库连接层在未显式配置时补充 5 秒连接、读取和写入超时，继续强制 UTC 与时间解析配置，不覆盖自定义超时和 TLS 选择。
- 新增只读迁移核验脚本，可分别预检源库和目标库，并比较表、精确行数、Migration、列、索引、外键和 UTC 时间边界。
- 新增数据库跨区域迁移 Runbook，记录预检、备份、停写、导出、恢复、验证、连接切换、冒烟、观察和回滚边界。
- 本地与生产部署职责、连接参数、TLS 风险和敏感文件忽略规则同步到示例配置、构建配置及相关文档。
- 未改写既有 Migration，未改变 Repository、Service、Model 和业务 API 语义；工具不自动迁移、切换或删除生产数据。

### 验证

- 数据库单元测试和 Go 全量测试通过，覆盖默认超时、自定义参数保留、TLS 参数和 UTC 标准化。
- 一次性 MySQL 环境完成全部 Migration 往返与同库源/目标快照核验，测试资源随后清理。
- Compose 配置、Shell 语法、敏感信息扫描和差异格式检查通过。

### 运维边界

- 迁移前必须创建平台备份并停写；完整库恢复必须包含 `schema_migrations`，禁止先对目标空库重复执行 Migration。
- 目标库产生新业务写入后，源库与目标库已分叉，不允许直接回切；需重新停写并评估增量数据。
- 凭据、真实连接端点、业务数据和单次生产操作记录不得写入仓库。
